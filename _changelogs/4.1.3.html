DnsHTTP – Changelog

Release 4.1.3 · Framework 4.13 — previously 4.1.2 / 4.11

Security

  • All domain names are normalised to punycode (IDN-safe) and strictly validated before they are used as file paths, shell arguments or named.conf entries; every named-checkzone / named-compilezone call now uses escapeshellarg(). Closes command-injection, path-traversal and config-injection paths.
  • $INCLUDE is stripped from user supplied zone data (web editor and API) — it made bind read arbitrary local files once the zone was written out.
  • API authentication now also matches the requested section, and rejects blocked, disabled or unconfirmed accounts. Previously a blocked user kept full API access as long as the token existed.
  • x_class_crypt now uses authenticated encryption: AEAD tag for GCM/CCM ciphers, encrypt-then-HMAC otherwise. Tampered ciphertext returns false instead of garbage.
  • CSRF tokens, session keys, API tokens and generated passwords now come from random_bytes() / random_int() instead of mt_rand() / str_shuffle(); all token comparisons use hash_equals().
  • Session ID is regenerated on successful login (session fixation). Auth cookies are now HttpOnly, SameSite=Lax, path=/ and Secure over HTTPS.
  • Every unserialize() call hardened with allowed_classes => false.
  • Output escaping added for comments, table cells, conflict page, search form, zone serials and RSS items (feed links/covers are now restricted to http(s) URLs).
  • New per-server option “Allow invalid SSL certificates”. When disabled, outgoing API requests verify peer and host — verification used to be off unconditionally.
  • Comment upvotes moved from GET to POST with a CSRF token; login_as() got a privilege guard with an optional minimum rank.

Replication & Sync

  • sync.php now takes an exclusive lock — two overlapping runs could leave bind with a half-written configuration.
  • _api/list.php always answers plain serialised data. An empty domain list was returned gzip+base64 encoded, which the reading side could not decode — a peer with zero replicable domains was reported as a broken connection.
  • Replicated domains are no longer wiped when the server list query fails; a transient database error used to take every slave zone out of service.
  • Domains flagged set_no_replicate are now really kept out of the published registration table, and existing rows are dropped within the same run.
  • Preferred-entry handling fixed: exactly one preferred row per name across both tables. Two preferred rows produced two zone stanzas for one name and bind rejected the whole generated config.
  • Slave zones require a valid master IP (IPv4, falling back to IPv6); unresolvable local hostnames are no longer written into allow-transfer.
  • Server status “Compressed” is only reported after the authenticated probe succeeded; the SSL setting is passed through all API calls.
  • Fixed the broken slave-domain cleanup query (a second WHERE instead of AND) and stale parameter bindings that silently discarded zone-check diagnostics.
  • Zone names declared by more than one source are now logged as a warning instead of silently overwriting each other.

Zone Handling & Editor

  • SOA serial matching rewritten. The old pattern could run across newlines and rewrite the number of a completely unrelated record.
  • The SOA serial is now auto-incremented and stored on every zone save — both in the web editor and through the API — so slaves actually pick up changes.
  • Serial rollover past 99 edits per day now moves to the next day’s date instead of getting stuck.
  • The editor no longer drops unknown record types. Opening a zone and pressing save silently deleted DS, DNSKEY, TLSA, SSHFP, SVCB, HTTPS, NAPTR, DNAME, …
  • The leading $ORIGIN line is only stripped when it really is one — before it ate the $TTL line, or the first character when the text had no line break at all.
  • Saving zone data of a replicated (slave) domain now reports an error instead of a false success.

Interface & Administration

  • Duplicate domain creation is detected platform-wide (web + API). The failed insert used to be swallowed and still reported as success.
  • Creating a name that is already served locally or replicated in now warns that the entry starts in conflict.
  • Server create/edit forms got the SSL verification checkbox.
  • “Last run … minutes ago” on dashboard and debugging page is correct again for runs older than a day.
  • Dashboard label corrected to “Slave Domains (Registered)”; blacklist hint points to ./_cronjob/blacklist.php.
  • Password length check off-by-one fixed (33 → 32), labels now state “Min 8”, username error message corrected to 20 characters.
  • Footer and login page: Impressum / Help / Github links now each test their own constant.
  • Cookie banner redirects back to the actual request URI instead of a rebuilt one.

Framework & Setup

  • x_class_mysql: decrease() actually decreases now (it was writing the increase field); debug error_log() on every insert removed.
  • x_class_user: password policy checks count occurrences correctly via preg_match_all() — the rules were effectively inverted. confirm_user() no longer fails on an undefined variable.
  • x_class_mail: failed sends are logged as failures instead of successes.
  • x_class_ipbl: ip_counter($ip) now uses the IP that was passed in.
  • Comment counters and upvote state are stored/read correctly; x_class_referer returns its result instead of discarding it.
  • File and directory modes are converted with octdec() — permissions were passed as strings; the log directory is created at its real path instead of a folder literally named folder.
  • Installer check parses memory_limit / post_max_size with M/G/K suffixes and unlimited values.
  • Schema: new columns set_no_replicate (domains) and ssl_insecure (servers), added automatically on upgrade; AUTO_INCREMENT columns are no longer UNSIGNED.
